# Contributing to AccessLint

Thanks for your interest in contributing to AccessLint. This is a student-led hackathon project for **PS-09: Accessibility Linter for OSS Frontends**. The project is currently being planned, and implementation has not started yet.

## About AccessLint

AccessLint aims to help frontend developers identify accessibility issues in their websites and understand how to fix them. The project is still taking shape, so its implementation details may change.

## Ways to Contribute

You can help by:

- Reporting bugs or suggesting features.
- Improving project documentation.
- Adding test cases and sample pages.
- Helping implement accessibility checks.

## Getting Started

When you are ready to contribute:

1. Fork the repository on GitHub.
2. Clone your fork to your computer.
3. Create a new branch for your changes.
4. Make your changes and test them where possible.
5. Commit your changes and push the branch to your fork.
6. Open a pull request describing what you changed and why.

Setup instructions will be added when implementation begins. There are no application installation or run instructions yet.

## Contribution Guidelines

- Keep changes focused and easy to review.
- Use clear variable and function names when writing code.
- Explain the purpose of significant changes in your pull request.
- Do not claim an accessibility issue is detected unless that check has been tested.
- Avoid changes that are unrelated to the contribution.

## Reporting Issues

When reporting an issue, describe the problem clearly. Include steps to reproduce it when applicable, what you expected to happen, and what actually happened. Screenshots or error messages can help when they are relevant.

## Good First Contributions

- Research and document common frontend accessibility violations.
- Prepare sample HTML pages containing missing image alt text and inaccessible form labels.
- Help document how accessibility scan results should be displayed to developers.

## Pull Request Checklist

- [ ] The pull request clearly describes the changes.
- [ ] Relevant changes have been tested, or the pull request explains what could not be tested.
- [ ] Related documentation has been updated.
- [ ] The changes are focused and avoid unrelated work.

## Code of Conduct

Communicate respectfully and give constructive feedback. Help make the project welcoming and useful for everyone contributing.
